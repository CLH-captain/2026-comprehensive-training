# Phase 3：仿真数据集实施计划

## 目标

基于固定随机种子 `20260822` 生成可解释、可复现且满足外键与业务约束的校园社团活动数据，一次生成数据图后可写入 MySQL、导出 CSV，并生成质量报告。

## 实施步骤

1. 定义数据生成配置、学院活动偏好和确定性随机工具；覆盖两校区、两学期、12 个学院、约 40 个专业、6 类社团、45 个社团、7 类活动和约 24 个场地。
2. 先在内存中生成完整数据图：3000 名学生、长尾社团成员关系、300～350 场活动、18000～25000 条报名和至少 16000 条签到。
3. 让年级、学院偏好、社团热度、成员身份、月份峰谷和活动规模共同影响报名与到场，保留取消活动、取消报名、缺席和少量热门活动等合理异常。
4. 实现独立质量校验器，检查数量、引用、唯一性、时间、容量、年级分布、社团长尾、活动规模、月份趋势及到场率，并输出结构化 `data_quality_report.json`。
5. 实现 CSV 导出；文件写入临时目录后原子替换，避免失败时留下半套导出文件。
6. 实现 MySQL Seed CLI；默认拒绝非空业务库，`--reset` 仅允许精确的项目开发库或测试库，并在单事务中清理和写入。
7. 为固定种子、目标数量、分布规律、质量检查、CSV 和数据库安全保护编写测试。
8. 在 `szut_club_agent_test` 完成重置与写入验证，在开发库执行正式 Seed，最后运行后端全量测试、Ruff 和数据质量检查。

## 验收条件

- 同一 seed 生成相同数据摘要。
- 生成数量达到开发文档下限，所有质量检查通过。
- MySQL 与 CSV 条数一致，开发库与测试库均可由项目账号读取。
- 重置保护无法作用于任何非项目数据库。
